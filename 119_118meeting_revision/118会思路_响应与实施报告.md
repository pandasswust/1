## 2. 需要哪些数据集？

已在 119 论文第 4.1 节新增数据集清单表（`tab:dataset_card`），并建立 `dataset_cards/`：

1. **NYU Depth V2 验证子集**：1449 帧中仅 17 帧含 ≥100 个楼梯像素；最终 51 帧，17/类；类别 id 为 Flat=11、Stairs=215、Obstacle/chair=5。原始 2.97 GB `.mat` 不随包分发，提供提取脚本和 51 帧 RGB/深度/掩码/叠加图。
2. **Go1 Gazebo 街道校准集**：351 帧（Flat 59、Stairs 152、Obstacle 85、Tactile 55），24 维特征，ROI 为 `(0.15,0.85)x(0.35,0.98)`。
3. **Go1 闭环运行集**：3 次正常 + 3 次退化，每次 30 s；5 Hz 位姿更新，8-12 s 与 18-22 s 两段 4 s 中断。
4. **独立 6-DoF SAPF 仿真**：20 seeds，N=1000，30 s。
5. **跨光照边界数据**：同一几何、暖暗光+浓雾的 shifted world，零样本部署。
6. **原始 NYU 归档**：外部获取，不重分发。

## 4. 实验是否够？

原稿已有聚类、校准、跨光照、独立与闭环滤波，但确实缺少：
- 单独聚类效果图；
- 逐类错误分析；
- 配对统计显著性；
- CPU 运行时间；
- 标签效率曲线；
- 真实 RGB/深度/掩码彩色图。

这些已分别由 E3、E11、E0 补齐。新增结果还暴露了一个必须诚实报告的细节：严重退化下与 **Depth only** 的 ACC 差异不显著（60.0% vs 59.6%，p=0.797），但本方法取得最高的 severe macro-recall（60.0%），障碍物召回 29.7% vs 23.5%，且在干净数据上显著优于 Depth only（+6.08 pp，p=9.4e-5），并且不需要“哪个模态损坏”的 oracle。论文中已明确写出该 tie，而不是通过挑选协议制造更大差距。

剩余边界：NYU-51 是 verified pilot subset，Go1-351 是单一仿真街道；大规模户外多场景仍是 future work，已在 Discussion 中声明。

## 7. 考虑清楚

实施时坚持了三条原则：
- **可审计**：每个数字都绑定数据、重复次数、指标和 CSV/JSON；
- **不回避负结果**：Depth-only tie、Flat 类混淆、跨光照下降均明确报告；
- **不过度声称**：方法优势被表述为“无需模态 oracle 的鲁棒性 + 校准语义读出 + 下游状态估计收益”，而不是单纯追求一个 pilot 子集上的 ACC 数字。
